## Exercise 13: Use a Project across separate chats {#exercise-13-use-a-project-across-separate-chats}

::: {.callout-note collapse="true" appearance="minimal" icon=false title="Open exercise"}

**Scenario:** An event may require several conversations. A Project keeps related documents, decisions and chats together.

**Use:** [06_simulated_event_brief.md](materials/06_simulated_event_brief.md) and [10_simulated_event_status_update.md](materials/10_simulated_event_status_update.md).

1. Open **Projects**, create *Interdisciplinary Staff Afternoon*, and add the two fictional files to the **Project** (not just a single chat).
2. If the Project supports instructions, add: *For this event, distinguish confirmed decisions, proposals and missing information. Treat the latest dated update as more recent than the original brief. Never claim a booking or invitation has been completed unless a document says so.*
3. In **Chat 1**, ask: *From the event brief, what needs doing, who owns it, and what is undecided?*
4. In **Chat 2**, ask: *Using the event brief and the latest status update in this Project, draft a concise status email for the organisers. What changed, and what is still open?*

**Check:** Did Chat 2 use the updated decisions while keeping the original event's goals and requirements? Did it distinguish a room being *available* from *booked*? Did it avoid treating a proposed registration deadline as agreed?

**Note:** Shared Project context may not be applied consistently across chats. If a detail is missing or wrong, refer the AI explicitly to the relevant project file or save a key decision in project knowledge (where available), then verify the answer again.

:::
